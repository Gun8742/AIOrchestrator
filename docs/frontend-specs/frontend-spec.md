# Frontend Specification

## เป้าหมาย

แสดงออฟฟิศ Pixel Art และให้ผู้ใช้สั่งงาน ติดตาม และตรวจผลของ Coding Agent ได้จากหน้าเดียว โดยข้อมูลและสถานะมาจาก Backend

## ขอบเขต MVP

- เลือกโปรเจกต์ที่ Backend อนุญาต และส่งคำสั่งภาษาไทยหรืออังกฤษให้ Codex
- แสดงตัวละคร Codex ในออฟฟิศ พร้อมสถานะ `queued`, `running`, `waiting_for_user`, `completed`, `failed` หรือ `cancelled`
- คลิกตัวละครหรืองานเพื่อดูคำสั่ง เหตุการณ์ ผลลัพธ์ ข้อผิดพลาด และเวลาที่เกี่ยวข้อง
- แสดงคำขออนุมัติและให้ผู้ใช้ตอบเมื่อ Backend และ integration รองรับ พร้อมระบุการกระทำที่ขออย่างชัดเจน
- หยุดงานที่ยังทำงานอยู่ และแสดงผลการหยุดจาก Backend
- หลัง reload หรือเชื่อมต่อใหม่ โหลดสถานะล่าสุดและประวัติจาก Backend

## หน้าจอ

1. **Office:** ฉากออฟฟิศ 2D ตัวละคร โต๊ะ และป้ายสถานะ คลิกหรือใช้ keyboard เลือก Agent ได้
2. **Task panel:** เลือกโปรเจกต์ กรอกคำสั่ง ส่งงาน และดูรายการงาน
3. **Activity panel:** แสดง timeline ของงานที่เลือก พร้อมผลลัพธ์และรายละเอียดคำขออนุมัติ

ฉากใช้ animation เป็นสัญญาณประกอบ เช่น นั่งทำงานขณะ `running` และแสดงสัญลักษณ์เมื่อ `waiting_for_user` ต้องไม่สร้างเหตุการณ์หรือความคืบหน้าปลอม หากไม่มีข้อมูล Subagent ให้แสดงเฉพาะ Agent หลัก

## Interaction และสถานะผิดพลาด

- ปิดปุ่มส่งระหว่างส่งคำขอเดียวกัน และแสดง validation เมื่อไม่ได้เลือกโปรเจกต์หรือไม่ได้กรอกคำสั่ง
- แสดงสถานะเชื่อมต่อและข้อผิดพลาดที่อ่านเข้าใจได้ หากหลุดให้ reconnect แล้วโหลด snapshot ล่าสุด
- การกดหยุดแสดงสถานะกำลังส่งคำขอจน Backend ยืนยัน ไม่สรุปว่างานหยุดแล้วก่อนเวลา
- Layout ใช้งานได้บน desktop และหน้าจอขนาดเล็ก โดย panel และข้อความไม่ถูกบังโดยฉาก
- ทุก action ใช้ keyboard ได้ มีชื่อสำหรับ screen reader สีไม่ใช่ตัวบอกสถานะเพียงอย่างเดียว และเคารพ reduced motion

## การเชื่อมต่อ

ใช้ HTTP สำหรับโหลดข้อมูลและสั่งงาน และ Server-Sent Events (SSE) สำหรับเหตุการณ์แบบ real-time ตาม contract ใน [Backend specification](../backend-specs/backend-spec.md) เมื่อ reconnect ให้รอ SSE ready แล้วโหลด snapshot และ reconcile events ตาม feature spec ไม่อนุมานสถานะจาก animation

## แนวทางเทคนิคที่เสนอ

- React + TypeScript และ Vite สำหรับ UI; ใช้ Canvas หรือ DOM/CSS สำหรับฉากตามความเหมาะสมหลังทดลอง prototype
- แยก scene rendering ออกจาก task state เพื่อให้เปลี่ยน artwork ได้โดยไม่เปลี่ยน orchestration
- เริ่มด้วย asset ขนาดเล็กและ animation เท่าที่จำเป็น ยังไม่เลือก game engine หรือแหล่ง asset

## เกณฑ์ยอมรับ

- ผู้ใช้ส่งงาน เห็นสถานะเปลี่ยน ดูผลลัพธ์หรือข้อผิดพลาด และหยุดงานได้จาก UI
- Reload แล้วงานและสถานะล่าสุดยังปรากฏ; การหลุดเครือข่ายแสดงให้ผู้ใช้ทราบ
- คำขออนุมัติที่รองรับแสดงรายละเอียดและตอบได้; คำขอที่ตอบผ่าน integration ไม่ได้ต้องแจ้งอย่างชัดเจน
- ควบคุม action หลักด้วย keyboard และใช้ได้เมื่อเปิด reduced motion

## นอกขอบเขต MVP

ตกแต่งออฟฟิศเอง, multiplayer, ระบบเกม และการแสดง Subagents แบบละเอียดที่ยังไม่มี event รองรับ
